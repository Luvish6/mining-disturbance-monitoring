# Codex project workflow

Preserve this existing B.Tech research project, scientific methodology, functioning Phase 1–3C code and local outputs. Make only requested changes. Inspect actual evidence; implemented code and synthetic scores are not completed scientific results.

For EVERY meaningful development task:

1. Read applicable instructions. Inspect `git status --short --branch`, recent log, branch/upstream and `git remote -v` BEFORE editing. Identify unrelated changes; never overwrite/discard or silently commit them.
2. Preserve original ZIPs, research results and model artifacts. Work within scope. Do not fabricate labels, metrics, imagery coverage, dates, completion milestones or commits.
3. Run relevant tests/validation using the existing environment. For production/regression changes run `python -B -m pytest -q -p no:cacheprovider` with a fresh permitted temporary directory if required. Existing synthetic training tests do not represent real research training. Do not train/evaluate real models or run expensive exports unless specifically authorized by the actual task.
4. Review `git diff` and `git diff --check`. Stage EXPLICIT task-related publication-safe paths, then review `git diff --cached`, `git diff --cached --stat` and `git diff --cached --check`.
5. Run `python scripts/audit_publication.py` against the staged snapshot. Manually check secrets, sensitive local paths, redistribution restrictions and size. Never publish `.env`, credentials/tokens, raw ZIPs, satellite rasters/restricted derivatives, original third-party geodata, model artifacts or large generated datasets. No `git add -f`, Git LFS or hook bypass to evade safeguards. Small original audited text/tables may be copied to docs/reports; leave imagery/local outputs excluded.
6. Once the task is meaningful, COMPLETE and VERIFIED, create a descriptive local commit (`docs:`, `test:`, `feat:`, `fix:`). Use real current timestamps/configured author identity. No filler/empty commits, backdating, fake history, amend/rebase of published work, force-push, destructive reset or deletion of local research data.
7. Push the verified commit when auth/permissions allow. Remote: `https://github.com/Luvish6/mining-disturbance-monitoring.git`; intended publication branch/upstream: `main` / `origin/main`. Respect any explicitly requested task branch; do not silently merge it. Recheck remote refs. If remote advanced, inspect/reconcile normally; never force-push.
8. Verify the remote branch SHA equals the pushed commit; verify the GitHub commit/tree when connector access permits. Never claim push success based on an attempt alone.
9. Report commit hash/URL, changed files, test/validation results and push status. Record progress and important available prompts/summaries faithfully. Retrospective summaries are not verbatim prompts or fabricated historical commits.
10. If tests fail, conflicts occur or sensitive/restricted files appear in the proposed publication, STOP commit/push and report the problem. If network/auth blocks push, preserve the verified local commit and state it was NOT pushed. Do not broaden scope or bypass safeguards to hide failures.

Research constraints: seasons `[2023-11-01,2024-04-01)` and `[2024-11-01,2025-04-01)`; 5 km spatial design and independent reference admission stay unchanged. Districts are not catchments. LISS-IV green/red/NIR DN is not surface reflectance; signal is not cloud-free usability. Application polygons/bare soil are not mining labels; land disturbance does not establish illegality or river causation. KORPET/Sumon pair remains under quality review. Do not start Phase 4 or real training until scientific gates pass. Read docs/research-progress.md and docs/reference/REAL_REFERENCE_PROTOCOL.md.

Use the existing local virtual environment when available (may be outside checkout); never publish machine-specific location/secrets. Fresh clones use README setup. Documentation-only changes normally need publication/link/schema review rather than retraining tests, unless the user requires full tests. Hooks are tracked but fresh clones must install them with `git config core.hooksPath .githooks`; never bypass them. AGENTS.md gives future sessions durable instructions; it is not a background scheduler or an auth grant.
