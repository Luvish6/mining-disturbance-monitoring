**Base-paper selection:** MineC2FNet addresses the actual bottleneck—coarse/weak footprints versus scarce independently interpreted boundaries—and supplies a current official implementation. This is a methodological base for keeping pseudo-label and fine-reference streams separate, not approval to reproduce a full teacher–student architecture. Its static target, TensorFlow implementation and missing date/rights checks preclude direct integration. TerraMind supplies the candidate encoder and EUSAR provides a relevant SAR/optical ablation reference. The JSTARS code link was unavailable, MM-SAM has incompatible source data, and EuroMineNet has unresolved local gates. These practical differences outweigh recency alone.

No novelty is established by combining indices, pseudo-labels, U-Net and a foundation model. A possible contribution is a reproducible Indian temporal dataset-generation protocol with explicit uncertainty, geography and evidence separation, contingent on real samples, rights and independent review. Do not claim it is the first such dataset or that it detects mining accurately.

## 3. MineC2FNet: dataset and code audit

[Official code](https://github.com/risqiutama/MineC2FNet), revision `8fbaf6596591a7222a8a5e6c1c6c41d5cb5ca99a`, exposes coarse/fine configs and teacher–student training. The repository uses six-channel RGB+NIR+SWIR1+SWIR2 with binary mining/non-mining masks; its Linux/Conda Python 3.9-era TensorFlow environment is not the current Windows PyTorch runtime.

The [paper](https://arxiv.org/html/2605.24460v2) describes 219 expert-harmonized fine images across 39 countries/six continents, 153/22/44 TRAIN/VAL/TEST; 200 have SWIR. Sentinel and Landsat inputs vary in resolution. Examples in the published TRAIN roster include Zawar, Khetri Group and Malanjkhand in India; this identifies no accepted local sample or seasonal change event. No dataset imagery/masks were downloaded or inspected. Exact acquisition dates, patch georeferencing, original site grouping, independent annotation lineage and rights still require payload-level verification before any reuse. Foreground-free pixels are not automatically independently verified negative controls.

The [LICENSE](https://raw.githubusercontent.com/risqiutama/MineC2FNet/main/LICENSE) is CC BY-NC 4.0 for original code. [NOTICE](https://raw.githubusercontent.com/risqiutama/MineC2FNet/main/NOTICE) explicitly leaves datasets, pretrained models and dependencies under their respective owners' terms. A Google Drive dataset/checkpoint link exists, but this is not a verified license grant or evidence of matching 2023–2025 observations. **Decision: method reuse conditional; dataset admission NO-GO pending those checks.** Do not port its entire architecture or environment merely to satisfy a model name.

## 4. TerraMind: technical feasibility

Audit sources: [IBM repo](https://github.com/IBM/terramind) revision `53d61da09213c2c3629931b6322f94cce617886a`; [tiny model card/files](https://huggingface.co/ibm-esa-geospatial/TerraMind-1.0-tiny), revision `2b5ac0a3ed7dd7e922ccfd595b56607f342df343`; [TerraTorch registration code](https://github.com/torchgeo/terratorch/blob/297b9dea723a147aef6b778041af111b71494e59/terratorch/models/backbones/terramind/model/terramind_register.py). Code/model card are Apache-2.0; underlying imagery/data rights remain separate. Tiny, small, base and large pretrained variants exist. Choose **tiny raw encoder, frozen backbone**, for a proposed smoke test; no generations/TiM/tokenizers are needed initially.

- **Weights:** the official tiny `TerraMind_v1_tiny.pt` file is **211,873,402 bytes (202.06 MiB)**; metadata SHA-256 is `e56ea9ebcd4451078b9ca4893d5cd8a89bbee376ae16829c3e7fbbbc76de0eba`. This is the listed file size/hash, not a downloaded or locally validated checkpoint. Tiny registration is 12 encoder layers, width 192, three heads. Do not assume the model-card generic width-768 output example describes tiny.
- **Inputs:** supported raw modalities include S2L2A, S2L1C, S1GRD, S1RTC, DEM and RGB. Default S2L2A uses 12 actual bands; selected named subsets are supported. For our six-band cache, map B2/B3/B4/B8/B11/B12 to BLUE/GREEN/RED/**NIR_BROAD**/SWIR_1/SWIR_2. B8 is not NIR_NARROW (B8A). VV/VH are S1GRD dB; do not relabel power values as dB or GRD as RTC.
- **Grid:** optical native 10/20/60 m and radar support do not become finer through interpolation. The [official modality definitions](https://raw.githubusercontent.com/torchgeo/terratorch/main/terratorch/models/backbones/terramind/model/modality_info.py) use patch embedding size 16; model-card examples are 224-pixel tensors, not a universal 224 m grid. A later 128-pixel, 10 m pilot must pass the pinned implementation's positional/grid smoke test. Existing 30 m index caches cannot masquerade as native 10 m spectra.
- **Normalization:** use the selected pretrained modality's documented constants and correct units exactly once. The [official example config](https://raw.githubusercontent.com/IBM/terramind/main/configs/terramind_v1_base_sen1floods11.yaml) expects optical magnitudes in reflectance×10,000, not 0–1 values normalized by those same constants. S1GRD VV/VH means are −12.599/−20.293 dB and SDs 5.195/5.890. The selected S2 subset needs matching entries from the official band table. Preserve invalid masks separately. Do not fit backbone scaling to VAL or replace it with U-Net TRAIN statistics; any task-specific head scaling is TRAIN-only.
- **Fine-tuning:** official TerraTorch examples support segmentation heads, backbone freezing and a temporal wrapper. Start with feature extraction and a small head; LoRA is an investigation, not an implemented/validated adapter. Derived EVI/BSI/slope planes cannot be inserted into arbitrary pretrained raw-modality slots. If used, they require an explicitly tested separate feature/head path. Generated modalities must never enter independent evidence or label columns.
- **Environment:** [TerraTorch metadata](https://raw.githubusercontent.com/torchgeo/terratorch/main/pyproject.toml) declares Python ≥3.10, torch >2.0 and many dependencies; IBM setup recommends Python ≥3.11. Python 3.13 meets a declared minimum, not verified Windows/CUDA compatibility. TerraTorch, timm, transformers and huggingface_hub were absent locally. No dependency install was attempted. Use a separately approved isolated environment; never replace the working environment in place.

**Decision: conditional engineering feasibility, NO-GO for training now.** First verify units, raw bands, masks, checkpoint/hash and one bounded forward pass in an approved environment. Full fine-tuning, generative branches and published GPU performance are not justified by this audit.

## 5. Candidate feature contract — proposal, not execution

Existing NDVI, BSI, VV/VH, elevation and slope can be reused in their applicable caches; NDTI remains a separate water-observability diagnostic. EVI/SAVI/NBR/NDMI/MNDWI are not implemented in the current canonical land stack. With scaled reflectance N=B8, R=B4, G=B3, B=B2, S1=B11, S2=B12, investigate:

| Feature | Formula / units | Support / purpose |
|---|---|---|
| NDVI | (N−R)/(N+R) | 10 m vegetation |
| EVI | 2.5(N−R)/(N+6R−7.5B+1) | 10 m; scaled reflectance required |
| SAVI | 1.5(N−R)/(N+R+0.5) | 10 m; soil-background sensitivity |
| BSI | ((S1+R)−(N+B))/((S1+R)+(N+B)) | Mixed 10/20 m exposed-ground context |
| NDBI | (S1−N)/(S1+N) | 20 m SWIR; exactly −NDMI on identical inputs |
| NBR | (N−S2)/(N+S2) | 20 m SWIR; disturbance/burn ambiguity |
| NDMI | (N−S1)/(N+S1) | 20 m moisture/vegetation context |
| MNDWI | (G−S1)/(G+S1) | 20 m; water screen, not pollution |
| VV, VH | seasonal backscatter dB | Native SAR support retained; orbit-specific |
| Elevation, slope | metres, degrees | Native terrain context; not mine class |

Do not present NDBI and NDMI as independent evidence. A proposed twelve-plane contract can omit NDBI and investigate NBR2=(S1−S2)/(S1+S2) instead, with native 20 m support and an explicit redundancy/utility ablation. EVI/SAVI/NDVI also share information. Final bands and constants must be frozen in 25B before processing. Differences of dynamic features are after−before; static terrain is not a temporal change. Mask zero denominators and invalid inputs rather than filling fabricated observations.

Phase 25B should first replay existing development caches and design three states: potential disturbance, potentially stable background, uncertain/ignore. Stable means a screening hypothesis, not independently verified non-mining. Fit any new rule calibration on eligible TRAIN only; retain current frozen rules/results unchanged. Assess persistence, SAR agreement and threshold sensitivity; agriculture, forestry, natural bare surfaces, roads, illumination and construction remain competing explanations. Pseudo-label agreement and human-admitted evaluation must have separate manifests and metric names.

## 6. Hardware, budgets and gates

Measured host: Ryzen 7 7840HS, 8 cores/16 logical processors; **15.29 GiB RAM**, **2.20 GiB available** and **26.70 GiB free disk** at inspection. `nvidia-smi` reports RTX 4060 Laptop GPU, **8,188 MiB total / 7,718 MiB free VRAM**, driver 610.91. WMI's roughly 4 GB AdapterRAM is not the reliable VRAM reading. Existing Python **3.13.2**, torch **2.15.0+cpu**, CUDA unavailable to torch. Hardware presence alone does not enable GPU execution.

**Proposed ceilings, requiring later approval:**

1. 25B: offline feature/mask unit tests first; zero downloads initially. Choose a maximum six existing, non-overlapping eligible development AOIs by metadata, never by spectacular change. If missing raw bands require acquisition, preregister all centers and one locked session only: at most 60 counted EE/metadata/URL/payload operations and 100 MB response bodies, including retries, with persistent ledger/cache reuse and stop-before-cap checks. No replacement AOIs or nationwide processing. Existing TEST guards remain mandatory.
2. Size estimate (not a download result): six 1.92 km squares on a 10 m common lattice are 192×192 cells each. A 23-plane float32 delivery (six S2 bands + two SAR bands per season, two static terrain layers, four counts and common validity) is **20,348,928 uncompressed bytes total (~19.41 MiB)**. Derived features are computed locally. Allow at most 200 MB for the bounded data/QA working set; actual GeoTIFF/response sizes and distinct sensor support must be checked before execution. Missing scene coverage can reduce eligible counts to zero. No generated sample count is promised.
3. 25C: freeze full-footprint group assignments before patching; use unique, non-overlapping windows, not inflated duplicated samples. CSV may describe sampled features but must retain pixel/group/mask identities and cannot leak into independent labels. Dataset card/rights matrix precede any release.
4. 25D: separately approve at most the tiny 202 MiB checkpoint (propose 250 MiB weight-transfer cap, excluding a separately estimated environment install). Reserve roughly 4–6 GB disk for an isolated environment; require ≥4 GiB available RAM before a CPU smoke test. Those are conservative planning limits, not measured model requirements. Batch one, 128×128, frozen encoder, no generated modalities; smoke ≤5 minutes, total process RSS ≤6 GiB; GPU peak target ≤6 GiB only after CUDA verification. If either limit fails, stop and request approval for a change. No fallback architecture is silently substituted.
5. Only after masks/splits/input and smoke gates pass, propose one ≤30-minute combined pilot, fixed seed 42 and maximum five epochs per model/head, U-Net versus frozen TerraMind tiny on identical eligible masks. Save resumable receipts; report incomplete runs. Runtime is a cap, not an expected measured completion time. On current free RAM and CPU-only torch, this training is blocked. No claim is made that a full foundation model can be trained on this laptop.

All proposed budgets are ceilings, not permission to acquire/train in 25A. Keep RF and every historical model/result intact. Later active-comparison changes require their phase approval. Public dataset/DOI preparation and any upload need separate source-rights, author and release approval. Restricted Planet/ISRO materials must not be bundled. Reviewed Sentinel input imagery alone still does not provide independent mining attribution.
